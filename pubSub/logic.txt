For the Publish-Subscribe (Pub/Sub) system, I would design a Publisher class that manages multiple topics using a map of topic names to Topic objects. Each Topic would contain a name and a list of subscribed users. A common Subscriber interface would define an update() method, and different subscriber implementations such as email, SMS, or mobile notification subscribers could implement this interface. Users can subscribe or unsubscribe from topics dynamically. Whenever a message is published to a particular topic, the publisher locates the corresponding topic and delegates the notification process to it. The topic then iterates through all its subscribers and invokes their update() method, delivering the message to each subscriber. This design naturally follows the Observer Pattern, where topics act as subjects and subscribers act as observers.
